# configs 配置表说明

这个文件夹只放业务方需要维护的小字典。普通系统走代码里的通用规则；只有通用规则处理不了、或者业务方明确确认了例外时，才改这里的表。

当前配置表全部使用中文文件名和 `.xlsx` 格式：

| 表格 | 用途 | 什么时候维护 |
|---|---|---|
| `系统文件夹映射表.xlsx` | 把 WP 的 `SID` 对应到 supporting 文件夹名 | supporting 实际目录名变化时 |
| `应用层管理员角色配置表.xlsx` | 按 `SID` 维护应用层管理员应有角色关键词 | 新增系统或角色变化时 |
| `支持性材料Sheet映射表.xlsx` | 说明每个检查节点对应 supporting Excel 的哪张 sheet | supporting 截图/清单 sheet 改名时 |
| `账号别名映射表.xlsx` | 把特殊账号写法统一成标准账号 | 开发人员权限匹配中出现账号/别名对不上时 |
| `中英文姓名对照表.xlsx` | 把开发人员中文名和英文名对应起来 | 开发人员清单和审阅导出使用不同语言姓名时 |
| `系统规则特殊覆盖表.xlsx` | 少数 SID 级业务例外 | 只有业务方明确确认系统例外时 |
| `人工覆盖表（预留）.xlsx` | 预留给最终结论人工覆盖（按 SID） | 当前主流程暂未读取 |

旧英文配置文件已经归档到项目根目录的 `旧英文配置备份/`，不再作为业务方日常维护入口。

## 1. 系统文件夹映射表.xlsx

解决的问题：

> WP 的 SID 和 supporting 压缩包里的文件夹名不完全一致。

列说明：

| 列名 | 必填 | 程序是否读取 | 通俗解释 | 示例 |
|---|---:|---:|---|---|
| `SID` | 是 | 是 | WP 中的系统唯一 ID，也是程序查找用的键 | `100001` |
| `实际文件夹名` | 是 | 是 | supporting 里真实存在的文件夹名 | `PMS_VMS公共凭证` |
| `备注` | 否 | 否 | 给维护人员看的说明 | `公共平台，Refer to 时使用` |

维护原则：

- 只在程序找不到文件夹时新增或修改。
- WP 必须提供 `SID` 列；程序不会再以系统名称作为文件夹映射键。
- `实际文件夹名` 必须和 supporting 文件夹名一致。
- 暂时无法确认 SID 的旧系统会以空 SID 占位，`实际文件夹名`写系统名，`备注`写`暂无SID`；程序会跳过这些占位行。

## 2. 应用层管理员角色配置表.xlsx

解决的问题：

> 核对 supporting 的「应用层管理员角色截图」中，角色列是否覆盖每个系统应有的应用层管理员角色。

| 列名 | 必填 | 程序是否读取 | 通俗解释 | 示例 |
|---|---:|---:|---|---|
| `SID` | 是 | 是 | 与 WP 的 `SID` 精确匹配；不使用系统名称 | `100001` |
| `管理员角色关键词` | 是 | 是 | 截图角色列中应出现的角色或关键词 | `用户管理-CSSC` |

程序对角色关键词自动执行规范化及保守模糊匹配；例如配置关键词为 `CSSC` 时，截图角色 `用户管理-CSSC` 可被识别为已覆盖。

## 3. 支持性材料Sheet映射表.xlsx

解决的问题：

> 某个检查节点应该去 supporting Excel 的哪张 sheet 找截图或清单。

列说明：

| 列名 | 必填 | 程序是否读取 | 通俗解释 | 示例 |
|---|---:|---:|---|---|
| `检查节点` | 是 | 预留 | 审阅流程里的检查项名称 | `需审阅应用层管理员账号` |
| `支持性材料Sheet名` | 是 | 预留 | supporting Excel 里对应的 sheet 名 | `应用层管理员账号` |
| `证据类型` | 是 | 预留 | 告诉程序这类证据大概怎么读 | `screenshot_or_excel` |
| `备注` | 否 | 否 | 给维护人员看的说明 | `可存放截图或导出清单` |

常见 `证据类型`：

| 值 | 意思 |
|---|---|
| `screenshot` | 主要是截图，需要 OCR |
| `screenshot_or_excel` | 可能是截图，也可能是 Excel 导出 |
| `excel_or_txt` | 主要是 Excel / TXT 清单 |
| `derived_check` | 不读单张截图，而是用已有数据做派生判断 |

当前说明：

- 这张表是配置模板，主流程里大部分 sheet 映射仍使用代码里的默认规则。
- 如果后续 supporting sheet 命名频繁变化，再把这张表完整接入主流程。

## 4. 账号别名映射表.xlsx

解决的问题：

> 同一个账号在不同材料里写法不同，默认清洗后仍然对不上。

列说明：

| 列名 | 必填 | 程序是否读取 | 通俗解释 | 示例 |
|---|---:|---:|---|---|
| `原始写法` | 是 | 是 | 材料里看到的原始写法，可以是账号、中文名、英文名或别名 | `SH Message 037` |
| `标准账号` | 是 | 是 | 程序最终统一使用的账号；当前主要用于开发人员权限匹配 | `SHMS9037` |
| `中文名` | 否 | 是 | 如果这条映射和某个人有关，可以填中文名 | `江丽` |
| `来源` | 否 | 否 | 这条映射是谁确认的或来自哪里 | `mentor` |
| `备注` | 否 | 否 | 给维护人员看的说明 | `OCR 可能误读` |

维护原则：

- 不要把所有账号都放进来。
- 只维护默认规则处理不了的特殊写法。
- 程序会对账号做基础清洗：去空格、去常见分隔符、统一大小写。

## 5. 中英文姓名对照表.xlsx

解决的问题：

> 开发人员清单写中文名，但账号审阅导出里的账号使用人写英文名。

列说明：

| 列名 | 必填 | 程序是否读取 | 通俗解释 | 示例 |
|---|---:|---:|---|---|
| `中文名` | 是 | 是 | 开发人员中文姓名 | `刘方强` |
| `英文名` | 是 | 是 | 开发人员英文姓名；程序读取时会去掉空格并统一转小写/大写后匹配 | `fangqiangliu` |

当前处理规则：

- 已根据业务方提供的 `中英文姓名对照表.xlsx` 生成到 `configs/`。
- 中文名会去掉首尾空格。
- 英文名会去掉所有空格并转小写，例如 `fangqiang liu` 会保存为 `fangqiangliu`。
- 程序匹配时也会统一标准化，所以导出表里写 `Fangqiang Liu`、`fangqiangliu`、`FANGQIANG LIU` 都可以匹配。

开发人员权限检查口径：

```text
开发人员出现在审阅导出表：
  用途 = 只读 -> 通过
  用途 != 只读 -> 未通过

开发人员不出现在审阅导出表：
  通过
```

如果姓名对照表还没维护完整，未匹配到的人不会直接失败；程序会在结果明细里提示，方便后续补表。

## 6. 系统规则特殊覆盖表.xlsx

解决的问题：

> 少数系统和通用规则不一致，并且业务方已经明确确认需要特殊处理。

这张表已将旧配置中能够由权威来源表确认 SID 的规则迁移完成。新增系统默认不会命中这里，会走通用规则。

列说明：

| 列名 | 必填 | 程序是否读取 | 通俗解释 | 示例 |
|---|---:|---:|---|---|
| `SID` | 是 | 是 | 需要特殊处理的系统 ID | `100001` |
| `是否合规支持平台` | 否 | 是 | 按 SID 标记合规支持平台；不再按系统名称判断 | `是` / `否` |
| `是否PMS_VMS` | 否 | 是 | 按 SID 标记 PMS/VMS；不再按系统名称判断 | `是` / `否` |
| `数据库服务器结论` | 否 | 是 | 覆盖“需审阅数据库服务器账号”的范围结论 | `是` / `N/A` / `Refer to DBA SOX服务器` |
| `数据库服务器原因` | 否 | 是 | 为什么要覆盖数据库服务器结论 | `业务方确认该系统使用独立数据库服务器` |
| `数据库账号结论` | 否 | 是 | 覆盖“需审阅数据库账号”的范围结论 | `是` / `N/A` |
| `数据库账号原因` | 否 | 是 | 为什么要覆盖数据库账号结论 | `业务方确认无数据库账号` |
| `是否检查SOD` | 否 | 是 | 是否强制检查前后台管理员 SOD | `Y` / `N` |
| `SOD原因` | 否 | 是 | 为什么要强制检查或说明 SOD | `业务方确认该工具需检查 SOD` |
| `发版工具前台结论` | 否 | 是 | 覆盖“需审阅发版工具发版账号”的范围结论 | `是` / `N/A` / `应用层Echo账号发版` |
| `发版工具前台原因` | 否 | 是 | 为什么覆盖发版工具前台结论 | `业务方确认由应用层账号发版` |
| `发版工具后台结论` | 否 | 是 | 覆盖“需审阅发版工具后台账号”的范围结论 | `N/A` / `Refer to PMS/VMS` |
| `发版工具后台原因` | 否 | 是 | 为什么覆盖发版工具后台结论 | `后台由公共平台管理` |
| `警告提示` | 否 | 是 | 需要在结果里提醒复核的文字 | `该系统结论需最终确认` |
| `备注` | 否 | 否 | SID 尚未取得时写 `暂无SID`；程序会跳过空 SID 行 | `暂无SID` |
| `来源` | 建议填 | 否 | 特殊规则来源 | `业务方邮件` |
| `确认人` | 建议填 | 否 | 谁确认的 | `张三` |
| `确认日期` | 建议填 | 否 | 什么时候确认的 | `2026-07-08` |
| `是否启用` | 否 | 是 | 是否启用这条特殊规则；填 `否` 可临时停用 | `是` |

维护原则：

- 没有业务方确认，不要填。
- 不要把普通系统填进来。
- 只填需要覆盖的列，不需要覆盖的列留空。
- 新系统不在这张表里时，会自动走通用逻辑。

## 8. 维护顺序建议

遇到问题时，按这个顺序看：

| 问题 | 优先维护 |
|---|---|
| 找不到系统 supporting 文件夹 | WP 的 `SID` + `系统文件夹映射表.xlsx` |
| 应用层管理员角色缺失 | `应用层管理员角色配置表.xlsx` 和 supporting 的 `应用层管理员角色截图` |
| 开发人员中文名和英文名对不上 | `中英文姓名对照表.xlsx` |
| 开发人员账号/别名特殊写法对不上 | `账号别名映射表.xlsx` |
| supporting sheet 改名 | `支持性材料Sheet映射表.xlsx` |
| 业务方明确说某系统和通用规则不同 | `系统规则特殊覆盖表.xlsx` |

## 9. 批量同步 SID

权威 System/SID 表变化后，在项目目录运行：

```bash
python sync_sid_configs.py --source "../各系统应用层管理员角色定义范围.xlsx"
```

脚本会同步四张系统级配置，并在 `output/SID配置同步报告.xlsx` 中列出迁移统计和待补 SID。系统名称只用于从旧配置做一次性、保守的迁移识别；运行时代码只以 SID 作为结果、规则、角色和文件夹的唯一键。

当前权威来源表仍缺少以下旧公共系统的 SID，因此脚本会把它们作为“空 SID + 暂无SID”占位行写入对应配置表，不会猜填或参与运行时匹配：

`DBAELK`、`DBASOX服务器`、`HJHJDE`、`INFRAJENKINS / Infra Jenkins`、`PAM`、`PMS&VMS / PMS/VMS`、`码云`。

不要为了“看起来完整”把所有系统都填进配置表。配置表只处理例外，通用逻辑仍然是主规则。
